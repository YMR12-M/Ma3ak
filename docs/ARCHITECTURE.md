# البنية المعمارية

## نظرة عامة

معاك تطبيق ويب بسيط من طبقتين، بخطوة بناء واحدة للفرونت إند (esbuild، من غير أي إعداد):

```
┌─────────────────────────┐         ┌──────────────────────────┐
│   المتصفح (Browser)      │  HTTP   │   Express Server          │
│                          │────────▶│   (Node.js)                │
│  dist/vendor.js (React)  │  JSON   │                            │
│  dist/app.js             │◀────────│  routes/*.js               │
│  dist/app.css            │         │  middleware/auth.js        │
│  (تلات ملفات مبنية مسبقًا) │         │  utils/access.js, codes.js │
└─────────────────────────┘         │  scheduler.js (كل دقيقة)   │
                                     └──────────┬─────────────────┘
                                                │ mysql2/promise
                                                ▼
                                     ┌──────────────────────────┐
                                     │   MySQL (schema.sql)      │
                                     └──────────────────────────┘
```

### القناة التانية: الإشعارات والتطبيق مقفول

كل اللي فوق بيشتغل بس والصفحة مفتوحة. التذكير بمواعيد الدوا - وهو الغرض الأساسي من
التطبيق - لازم يشتغل والمستخدم قافل كل حاجة. القناة دي منفصلة تمامًا:

```
scheduler.js                                        المتصفح (والتطبيق مقفول)
     │                                                        ▲
     │ 1. جرعة وصل ميعادها                                     │
     ▼                                                        │
utils/notify.js ── يخزّن الصف في notifications                 │
     │            ويقرر: يتبعت دفع ولا لأ؟                     │
     │            (تفضيلات + ساعات هدوء + أولوية)              │
     ▼                                                        │
utils/push.js ── يشفّر الرسالة بمفاتيح VAPID                   │
     │                                                        │
     ▼                                                        │
خدمة الدفع (جوجل لكروم، آبل لسفاري...)  ──────────────────────┘
                                          توصّلها للمتصفح
                                                  │
                                                  ▼
                                          sw.js (Service Worker)
                                          يعرض الإشعار + أزرار الفعل
                                                  │
                                    ┌─────────────┴──────────────┐
                                    ▼                            ▼
                        POST /api/doses/action        POST /api/notifications/ack
                        (خدته / فكّرني بعدين)          (سجل التوصيل)
```

**الـ Service Worker هو الحتة الوحيدة من الكود اللي بتشتغل والتطبيق مقفول** - وده اللي
بيخليه أهم ملف في الفرونت إند دلوقتي، مش مجرد كاش.

**المسارين دول (`/doses/action` و`/notifications/ack`) هما الوحيدين في التطبيق من غير
`Authorization`.** السبب مش إهمال: الـ SW **مش بيقدر يقرا `localStorage`** فمعندوش توكن
الدخول أصلاً. بدله بيتبعت مع كل إشعار توكن موقّع صلاحيته حاجة واحدة بعينها (جرعة واحدة،
أو إشعار واحد)، وبينتهي خلال ساعات. لو اتسرب، أقصى ضرر: تسجيل جرعة واحدة كـ"اتاخدت" -
مش قراية بيانات ولا دخول حساب. التفاصيل في [`utils/actionToken.js`](../backend/utils/actionToken.js).

نفس سيرفر الـ Express (`backend/server.js`) بيعمل حاجتين: بيسيرف ملفات الفرونت إند الاستاتيك (`express.static`، مع ضغط gzip وهيدرات كاش) وبيعرض الـ API تحت `/api/*`. يعني مفيش سيرفر منفصل للفرونت إند.

وقبل الاتنين، `helmet` بيحط هيدرات الأمان على كل رد - أهمها `Content-Security-Policy` بـ`default-src 'self'`. التطبيق بيخزّن توكن الدخول في `localStorage` وبيعرض بيانات مرضى، فأي XSS بيتحوّل لاستيلاء كامل على الحساب. السكريبتات الـ inline في `index.html` (تحديد المظهر قبل أول رسم + تسجيل الـ Service Worker) بتعدّي **ببصمة SHA-256 بيحسبها السيرفر من الملف نفسه وقت الإقلاع**، مش بـ`'unsafe-inline'`. التفاصيل في [API.md](API.md#هيدرات-الأمان).

## خطوة البناء (Build)

مفيش Vite ولا Webpack ولا أي إعداد - خطوة واحدة بملف واحد:
[frontend/build.js](../frontend/build.js) بيستخدم esbuild عشان يطلّع تلات ملفات في
`frontend/dist/`:

| الملف | جاي منين | الحجم (مضغوط) |
|---|---|---|
| `dist/vendor.js` | React + ReactDOM (UMD) من `node_modules` | 53 كيلو |
| `dist/app.js` | كل ملفات `js/` متُرجمة من JSX ومدموجة | 26 كيلو |
| `dist/app.css` | كل طبقات `css/` مدموجة | 41 كيلو |

المخرجات مكتوبة مقروءة (مش مصغّرة في سطر واحد) عشان تتفتح وتتتبع زي أي كود -
والأحجام فوق هي اللي بتوصل المستخدم فعلاً بعد ضغط gzip.

```
npm run build         # من مجلد backend
npm run build:watch   # بيعيد البناء مع كل حفظ
npm run dev           # بناء + سيرفر بـ --watch
```

**ليه اتضافت خطوة بناء أصلاً؟** قبل كده الفرونت إند كان بيحمّل React وBabel Standalone من
CDN، وملفات `.jsx` كانت بتتحمّل زي ما هي (`<script type="text/babel">`) وتتترجم في المتصفح
لحظة الفتح. الميزة كانت صفر إعداد؛ التكلفة كانت إن كل مستخدم بينزّل مترجم JSX حجمه ~3 ميجا،
ويستنى 26 ملف يتحمّلوا واحد ورا التاني، وبعدين يستنى الترجمة تخلص على الخيط الرئيسي - كل ده
**قبل** أول بكسل يترسم.

القياس (Lighthouse، موبايل، شبكة مخنوقة) قبل وبعد:

| | قبل | بعد |
|---|---|---|
| نتيجة الأداء | 57 | **99** |
| أول رسم للمحتوى (FCP) | 6.6 ث | **1.2 ث** |
| أكبر عنصر مرسوم (LCP) | 7.3 ث | **2.0 ث** |
| مؤشّر السرعة (Speed Index) | 11.8 ث | **1.9 ث** |
| إجمالي المنقول | 1052 كيلو | **182 كيلو** |

اللي اتعمل: الترجمة اتنقلت لوقت البناء (مفيش Babel في المتصفح خالص)، وReact والخطوط بقوا
مستضافين عندنا بدل CDN خارجي، والملفات الـ 26 بقت 3، وسيرفر Express بقى بيضغط الردود.

**مخرجات `dist/` متسجّلة في git عمدًا** عشان `npm start` يشتغل على أي نسخة جديدة من الريبو
من غير أي خطوة بناء. فيه فحص في CI بيتأكد إن اللي متسجّل هو ناتج المصدر الحالي - يعني لو حد
عدّل في `js/` أو `css/` ونسي يشغّل `npm run build`، الاختبارات بتفشل.

## قرارات تصميم أساسية

**١. المريض بيدخل بلينك، مش بباسورد.** كبير السن مش المفروض يتعامل مع تسجيل دخول أو باسورد. المتابع هو اللي بيضيف المريض (`POST /api/patients`)، والسيرفر بيولّد `access_token` عشوائي طويل بيتحط في لينك (`/access/<token>`). فتح اللينك ده = تسجيل دخول تلقائي (`POST /api/auth/access`). راجع [API.md](API.md#access-token) و[DATABASE.md](DATABASE.md).

**٢. شاشتين منفصلتين تمامًا حسب الدور.** `app.jsx` بيوجّه المريض لـ `PatientHome.jsx` (صفحة واحدة، بدون تابات، خط وأزرار أكبر) والمتابع لـ `AppLayout` (لوحة تحكم كاملة بتابات). القرار ده في الكود نفسه (`if (user.role === 'patient') return <PatientHome .../>`)، مش شرط CSS.

**٣. متابعين متعددين لكل مريض.** جدول `patient_caregiver` many-to-many - أكتر من ابن/بنت يقدروا يتابعوا نفس المريض عن طريق كود مشاركة (`link_code`)، وكل واحد فيهم بياخد نسخته من الإشعارات.

**٤. الـ scheduler بيشتغل بـ polling كل دقيقة** (`setInterval` جوه نفس عملية Node، مش cron خارجي أو queue). كان كل 5 دقايق، والرقم اتغيّر مع نظام المنبه: تأخير 5 دقايق على تنبيه دوا فرق محسوس (المريض بيبص على الساعة ويلاقي التطبيق ساكت). الاستعلامات كلها ماشية على فهارس (`idx_status_scheduled`) فالدورة رخيصة.

**٥. الجرعة حالة بتتصعّد، مش إشعار بيتبعت مرة.** الخط الزمني: منبه للمريض عند الميعاد → تذكير تاني بعد 15 دقيقة → "فاتت" + تنبيه المتابع بعد 30 → تصعيد حرج للمتابع بعد 45. المريض بياخد التنبيهات الأولانية لوحده، والمتابع مبيتزعجش غير لما يبقى فيه حاجة تستاهل - **متابع بيترن عليه في كل جرعة هيقفل الإشعارات خلال يومين، وساعتها التنبيه المهم مش هيوصله.**

**٦. حالة "اتبعت ولا لأ" في قاعدة البيانات مش في الذاكرة.** أعمدة `due_notified_at` / `reminder_notified_at` / `escalated_at` على `doses`، مش `Set` جوه عملية Node. السبب عملي: Render بينيّم الخدمة المجانية وبيعيد تشغيلها، وأي حالة في الذاكرة بتضيع - يعني المريض كان ممكن ياخد نفس التنبيه تاني، أو ما ياخدوش خالص.

**٧. منع تكرار الإشعارات قيد في قاعدة البيانات مش شرط في الكود.** `INSERT IGNORE` + `UNIQUE (user_id, dedupe_key)`. الطريقة القديمة (`SELECT` بعديه `INSERT`) فيها فجوة سباق حقيقية بين القراية والكتابة.

**٨. جلسة المريض سنة، وجلسة المتابع أسبوع.** المريض مالوش باسورد - بيدخل بلينك سري. لما توكنه كان بينتهي بعد أسبوع كان بيلاقي شاشة تسجيل دخول مالهاش أي معنى بالنسبة له. الواجهة كمان بتحتفظ باللينك على جهازه وبتجدّد الجلسة منه في صمت. الإلغاء الحقيقي بيحصل من "توليد لينك جديد"، مش من انتهاء الصلاحية.

**٩. تفضيلات الواجهة (الوضع الداكن، حجم الخط) متخزنة في `localStorage` على الجهاز نفسه، أما تفضيلات الإشعارات فعلى السيرفر.** التفرقة مقصودة: المظهر بيخص الجهاز (موبايل المريض عايز خط كبير، لابتوب المتابع لأ)، لكن تفضيلات التنبيهات بتخص الحساب - المتابع اللي بيغيّر موبايله المفروض يلاقي إعداداته زي ما سابها، مش يرجع للافتراضي من غير ما يعرف.

## نقاط ضعف معمارية معروفة

- **الـ scheduler نقطة فشل واحدة.** كل التنبيهات بتتبعت من السيرفر. سيرفر نايم (خطة Render المجانية) = صفر تنبيهات، مهما كان المستخدم مفعّل كل حاجة. مفيش fallback في الجهاز نفسه - ومفيش طريقة نظيفة لعمله في المتصفح أصلاً. التفاصيل في [DEPLOY.md](DEPLOY.md).
- **آيفون محتاج تثبيت.** Safari مبيدعمش Web Push إلا لو التطبيق متثبت على الشاشة الرئيسية - قرار من آبل مفيش التفاف حواليه. التطبيق بيكتشف الحالة ويعرض الإرشاد، بس نسبة من المستخدمين هتقف عند الخطوة دي.
- **مفيش تصعيد خارج التطبيق.** لو المتابع مش فاتح التطبيق ومش شايف الإشعارات، التصعيد بيقف عند حد الـ push. SMS أو مكالمة آلية هي الخطوة الجاية المنطقية.
- **تغطية الاختبارات في الواجهة ضعيفة** - الباك إند مغطى كويس دلوقتي (خط المنبه الزمني، التفضيلات، التوكنات، الصلاحيات)، بس منطق المكوّنات نفسه غير مغطى بأي اختبار.
- **schema.sql وملفات migration_*.sql مش موثقين كمصدر حقيقة واضح** - schema.sql فيها كل حاجة مدموجة (مناسبة لقاعدة جديدة)، والـ migrations تاريخية بس لترقية قواعد قديمة.
