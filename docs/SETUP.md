# تشغيل المشروع محليًا

## المتطلبات

- Node.js 18+ (السيرفر بيستخدم `node --watch` للتطوير، متاح من Node 18.11)
- MySQL 8+ (شغّال ومتاح على الجهاز)

مفيش أي متطلبات تانية. الفرونت إند ليه خطوة بناء واحدة (esbuild، بتتسطّب مع `npm install`)،
لكن **ناتج البناء متسجّل في الريبو** - يعني `npm start` بيشتغل على نسخة جديدة من غير ما تبني أي حاجة.
محتاج تبني بس لو عدّلت في `frontend/js/` أو `frontend/css/`.

## الخطوات

### ١. قاعدة البيانات

```bash
cd backend
mysql -u root -p < sql/schema.sql
```

ده بيعمل قاعدة `ma3ak` كاملة (الأمر نفسه بيعمل `CREATE DATABASE IF NOT EXISTS`، مش لازم تعملها إنت الأول). **متشغّلش ملفات `migration_*.sql`** بعد كده - دي لترقية قاعدة قديمة بس، والـ schema الحالي فيها كل حاجة مدموجة بالفعل (تفاصيل في [DATABASE.md](DATABASE.md)).

### ٢. متغيرات البيئة

```bash
cp .env.example .env
```

افتح `.env` واتأكد من بيانات الاتصال بقاعدة البيانات (`DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`)، وغيّر `JWT_SECRET` - السيرفر بيرفض يشتغل لو قصير أو غير موجود (16 حرف على الأقل). تقدر تولّد واحد عشوائي بالأمر:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### ٣. مفاتيح إشعارات الدفع (Web Push)

من غير الخطوة دي التطبيق بيشتغل عادي، بس **التذكير مش هيوصل والتطبيق مقفول** - وده الوضع الطبيعي 99% من الوقت. يعني أهم ميزة في التطبيق هتبقى معطّلة. السيرفر بيطبع تحذير واضح عند التشغيل لو المفاتيح ناقصة.

ولّد زوج المفاتيح مرة واحدة بس:

```bash
npx web-push generate-vapid-keys
```

حط الناتج في `.env`:

```
VAPID_PUBLIC_KEY=BN...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:you@example.com
```

`VAPID_SUBJECT` وسيلة تواصل معاك كصاحب السيرفر - خدمات الدفع بتطلبها في المواصفة عشان تقدر تبلّغك لو سيرفرك بيبعت غلط.

> **متغيّرش المفاتيح دي من غير سبب.** لو غيّرتها بعد ما ناس اشتركت، كل الاشتراكات القديمة بتبطل وكل مستخدم لازم يفعّل التنبيهات من الأول.

### ٤. تثبيت الحزم وتشغيل السيرفر

```bash
npm install
npm run dev     # بناء الواجهة + node --watch - بيعيد تشغيل السيرفر عند أي تعديل
# أو
npm start       # تشغيل عادي (بيستخدم ناتج البناء المتسجّل في الريبو)
```

لو هتشتغل على الواجهة نفسها، شغّل البناء في وضع المتابعة في تيرمينال تاني عشان يعيد
البناء مع كل حفظ:

```bash
npm run build:watch
```

ولو عدّلت في `frontend/js/` أو `frontend/css/`، **لازم تشغّل `npm run build` وتسجّل ناتج
`frontend/dist/` مع التعديل** - فيه فحص في CI بيتأكد من ده. التفاصيل في
[ARCHITECTURE.md](ARCHITECTURE.md#خطوة-البناء-build).

السيرفر بيشتغل على `http://localhost:3000` بشكل افتراضي (أو `PORT` من `.env`). ده بيعمل حاجتين مع بعض:
- بيسيرف الفرونت إند كامل (`frontend/` كملفات استاتيك).
- بيشغّل الـ scheduler (توليد الجرعات، منبه الجرعات، التصعيد، تذكير المواعيد) في الخلفية **كل دقيقة**.

**متبقاش مبعوت لازم تشغّل حاجة تانية للفرونت إند** - افتح `http://localhost:3000` في المتصفح وخلاص.

## تجربة سريعة بعد التشغيل

1. افتح `http://localhost:3000` → بوب "حساب جديد" → سجّل كمتابع (اسم + موبايل + باسورد).
2. من تاب "المرضى" → "إضافة مريض جديد" → هيديك لينك دخول (`access_token`) وكود مشاركة (`link_code`).
3. افتح اللينك في تاب تصفح تاني (أو نافذة خاصة) - هتدخل كشاشة المريض على طول بدون أي تسجيل دخول.
4. من شاشة المتابع، ضيف دواء بميعاد قريب من الوقت الحالي، وهتلاقي زرار "خدت الدوا" بيفتح لوحده في شاشة المريض.

### تجربة المنبه والتنبيهات

5. في شاشة المريض، دوس "تفعيل" في بانر التنبيهات (أو من ⚙️ الإعدادات ← تنبيهات الجهاز) واقبل إذن المتصفح.
6. من الإعدادات دوس **"ابعت تنبيه تجريبي"** - المفروض يوصل خلال ثواني. لو مجاش، المشكلة في الإعداد مش في التطبيق.
7. ضيف دواء بميعاد بعد دقيقة من دلوقتي، **اقفل التاب خالص**، واستنى. المفروض يوصلك إشعار فيه زرارين: "خدته ✓" و"فكّرني بعد 10 د" - والاتنين بيشتغلوا من غير ما تفتح التطبيق.
8. لو التطبيق مفتوح وقت الميعاد، هتشوف **شاشة المنبه** بدل الإشعار.

> **على الآيفون:** التنبيهات مش شغالة في Safari العادي خالص - لازم تضيف التطبيق للشاشة الرئيسية (مشاركة ← إضافة إلى الشاشة الرئيسية) وتفتحه من هناك. ده قرار من آبل، ومفيش أي طريقة نلتف حواليه. التطبيق بيعرض الإرشاد ده تلقائيًا لما يكتشف الحالة دي.
>
> وكمان: التنبيهات محتاجة اتصال آمن (HTTPS أو `localhost`). فتح التطبيق من IP الشبكة المحلية على الموبايل (`http://192.168.x.x:3000`) **مش هيشغّل التنبيهات** - المتصفح بيمنعها في السياق ده.

## تشغيل الاختبارات

اختبارات المنطق الحرج (صلاحيات الوصول، توقيت الجرعات، بوابة الـ JWT) بتشتغل بـ `node --test` المدمج في Node - مش محتاجة تثبيت أي حاجة إضافية ولا قاعدة بيانات شغالة:

```bash
cd backend
npm test          # اختبارات الباك إند بس (backend/test/)
npm run test:all  # الباك إند + الفرونت إند مع بعض (frontend/test/)
```

## مشاكل شائعة

- **"JWT_SECRET مش موجود أو قصير"**: السيرفر بيرفض يبدأ عمدًا - راجع الخطوة ٢.
- **`ECONNREFUSED` من MySQL**: اتأكد إن MySQL شغّال (`mysqladmin ping -u root`) وإن بيانات `.env` مطابقة.
- **`EADDRINUSE` على البورت**: فيه سيرفر تاني شغّال على نفس البورت (`lsof -i :3000` عشان تعرف مين وتقفله).
- **"VAPID_PUBLIC_KEY مش موجود"**: تحذير مش خطأ - السيرفر بيكمّل شغل والإشعارات بتتخزن جوه التطبيق، بس مفيش دفع للأجهزة. راجع الخطوة ٣.
- **التنبيه التجريبي بيرجع "مفيش أجهزة مسجّلة"**: الجهاز مسجّلش اشتراك لسه - دوس "تفعيل" الأول واقبل إذن المتصفح.
- **الإشعارات مش بتوصل على الموبايل رغم إنها مفعّلة**: اتأكد إنك فاتح على HTTPS أو `localhost`، ولو آيفون اتأكد إن التطبيق متثبت على الشاشة الرئيسية.
- **الجرعة اتسجّلت مرتين / التنبيه اتكرر**: لو قاعدة البيانات قديمة، شغّل `sql/migration_4_notifications.sql` - منع التكرار بيعتمد على قيد `UNIQUE` مش على كود.
- **"Unknown column 'has_image'" أو "recovery_hash"**: قاعدة قديمة محتاجة `sql/migration_5_gaps.sql`.
- **"Unknown column 'days_of_week'" أو "pills_left" أو "snooze_notified_at"**: قاعدة قديمة محتاجة `sql/migration_6_schedule_stock_vitals.sql`.
- **الواجهة بتفضل فاضية والكونسول بيقول "Refused to execute inline script"**: الـ CSP بتحسب بصمة SHA-256 لسكريبتات `index.html` الـ inline وقت إقلاع السيرفر. لو عدّلت `index.html` والسيرفر شغّال، **أعد تشغيله** - البصمات بتتحسب مرة واحدة عند الإقلاع.
- **رفع صورة الدوا بيرجع خطأ**: الصورة بتتصغّر على الجهاز قبل الرفع، فلو فشلت غالبًا الملف مش صورة سليمة. الأنواع المدعومة JPEG وPNG وWebP بس.
